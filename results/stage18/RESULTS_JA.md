# Stage 18 同期プリミティブとTriorのパッケージ化

Rustスケジューラにparkとunpark、成功済み操作をキャンセルから保護する再開経路、Rust製待機キューを追加。Event、Lock、Semaphore、MemoryChannelの基本操作をPython APIから利用できる。フラグ・所有者・セマフォ値・チャネルのバッファと配送データは現時点ではPython側が管理する。

Linux x86_64、CPython 3.12.14、Trio 0.35.0、Rust 1.100.0、PyO3 0.30.1。各条件7ペア、新規プロセス、単一CPU固定。CPU時間の中央値とペア速度比の中央値。

| 同期負荷（12,000操作） | Trio CPU | Rust CPU | 速度比 |
|---|---:|---:|---:|
| Event broadcast 600×20 | 93.75 ms | 28.48 ms | 3.29 |
| Lock 600×20 | 88.39 ms | 31.87 ms | 2.77 |
| Semaphore(8) 600×20 | 62.75 ms | 27.33 ms | 2.31 |
| MemoryChannel(0) | 83.95 ms | 28.80 ms | 2.87 |
| MemoryChannel(64) | 76.43 ms | 31.19 ms | 2.46 |

既存の600タスク比較はcheckpoint 3.25倍、周期実行11.14倍、混合4.71倍、待機キャンセル4.09倍、期限キャンセル1.46倍。過去ステージと同一ホスト条件とは限らない。

同期差分テスト22件、以前のランタイムテスト23件、計45件通過。イベント通知、ロック所有権とキャンセル競合、容量制限、チャネルの順序・クローズ・clone・キャンセルを基本ケースで確認。統計API、型チェック用の完全なジェネリクス、全公式テストなどは未対応。異常終了時のリソース解放、I/O、3.15、arm64、free-threadedも未検証。パッケージ名triorを導入し、実験用の旧モジュールも残した。
